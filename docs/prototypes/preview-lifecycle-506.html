Who should remember to manage previews?

A preview is a temporary copy of Unshelf for reviewing a pull request. The only decision here is which actions happen by themselves and which actions you want to trigger manually.

Four words used below

LabelPermission to have a preview.
CreateStart the preview for the first time.
UpdatePut the newest approved code on it.
DeleteRemove the preview and free one slot.

The shortest way to decide

If you dislike automatic updates, choose Balanced. You decide when a preview is created or updated, but closing the pull request still cleans it up automatically.

Choose Fully automatic only if pressing Update becomes annoying. Choose Fully manual only if you specifically want closed previews to stay online until you delete them yourself.
